# AutoDL 克隆抢机助手

一个用于 AutoDL 普通容器**克隆页面**和**租用新服务器页面**的 Chrome 扩展。先筛选满足显存要求且有库存的 GPU 型号，再检查该型号置顶的 **Top 3** 主机，符合价格、CUDA 和数据盘条件时创建一个实例。

当前版本：**v1.4.0**。

> **进入克隆或租用新服务器页面后，必须手动刷新一次（`F5` 或 `Ctrl+R`），右上角才会显示自定义面板。**
>
> 从 AutoDL 站内跳转时，扩展面板不会立即出现。请在目标页面完成刷新后再使用；每次重新进入界面时都要注意这一步。

## 下载与安装

1. [下载 v1.4.0 插件压缩包](downloads/autodl_clone_grabber_v1.4.0.zip?raw=true)，并解压到一个固定位置。
2. 在 Chrome 地址栏打开 `chrome://extensions`，开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择解压后的 `autodl_clone_grabber` 文件夹。**所选文件夹内应直接包含 `manifest.json`。**
4. 登录 AutoDL，从“容器实例”列表进入目标实例的“克隆”页面，或打开 [租用新服务器](https://www.autodl.com/create)。
5. **停留在目标页面，手动刷新一次。**看到右上角“AutoDL 克隆抢机助手 v1.4.0”后，核对面板显示的源实例 ID 或“租用新服务器”模式。

也可以通过本仓库的 **Code → Download ZIP** 下载源码；解压后，选择直接包含 `manifest.json` 的仓库文件夹加载。

## 使用步骤

1. 在页面选择“按量计费”和“1 张 GPU”。克隆模式请关闭“复制数据盘”；新租用模式请先选择地区和完整的**基础镜像**。
2. 在右上角面板中填写显存、价格、CUDA、扩容和刷新间隔。
3. 先点击 **“仅检查（不创建）”**。扩展会检查一轮，必要时选中候选主机并设置扩容，显示结果后停止，不会创建实例。
4. 确认设置后，点击 **“开始自动抢”**，核对确认框中的源实例或地区与镜像，以及筛选条件后启动。保持浏览器和标签页打开，避免电脑休眠。
5. 找到合格主机后，扩展会点击一次“创建并开机”。页面提示成功或扩展停止后，到 AutoDL 实例列表核对结果。
6. 需要停止时点击 **“停止”**。修改运行参数前，也应先停止再重新启动。

**创建并开机会产生 GPU 费用，付费数据盘另行收费。**扩展不会自动关机或释放实例；停止监控不会撤销已提交的创建操作。

## 租用新服务器

支持页面：`https://www.autodl.com/create`。

- 先在 AutoDL 网页中选择地区、“基础镜像”及完整的框架 / 框架版本 / Python / CUDA，再点击面板里的检查或开始按钮。扩展不会替你指定默认镜像。
- 自动刷新后，会恢复本次启动时确认的地区和基础镜像，然后重新查库存；所选镜像的 CUDA 是数字版本时，主机也必须支持该版本。
- 运行中修改镜像、地区或计费配置，会停止并提示重新启动。原地区或镜像选项下架、无法恢复时也会停止。
- **v1.4.0 的新租用模式仅支持基础镜像**，社区镜像、我的镜像暂不支持。克隆模式仍使用源实例系统，不受此限制。

## 可配置参数

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| 最低单卡显存 | 48 GB | 含边界；填 48 表示接受 48 GB 及以上 |
| 最低可扩容 | 300 GB | 主机必须提供的可扩容容量 |
| 实际扩容 | 300 GB | 创建时设置的付费数据盘扩容量；0 表示不扩容 |
| 单卡价格上限 | 7 元/小时 | 按页面当前单卡价格筛选 |
| 最低 CUDA | 12.8 | 按主机页面显示的兼容版本筛选 |
| 刷新间隔 | 5 秒 | 一轮结束后等待的时间，不是整轮扫描时长 |

每台主机的可扩容空间还必须足够容纳“实际扩容”值。参数可以按需修改，点击“保存设置”或启动时会保存；克隆设置按源实例区分，新租用使用独立设置和提交记录。

## 筛选流程

1. 动态读取当前地区可见的 GPU 型号，不依赖固定地区或固定型号名单。
2. 用型号标注的容量或已知标准型号的显存上限预筛。确定不满足显存门槛的型号，即使有库存也跳过。明确标注容量的变体优先按标注值判断。
3. 读取型号旁的 `(空闲数量/总数)`，只勾选有库存且通过预筛的具体型号。例如 `(0/350)` 跳过，`(1/296)` 表示有一张空闲卡。
4. **勾选具体型号后，只检查该型号列表置顶的前 3 台主机。**不遍历后面的主机，不滚动，不加载后续批次。前 3 台中的零库存或无效行会跳过，但不会补查第 4 台。
5. 前 3 台都不合适就检查下一个有库存且通过预筛的型号；本轮没有候选时，按设置间隔刷新再试。

未知型号的显存、主机价格、CUDA 和扩容空间需要读取实际主机信息判断。地区或型号列表发生变化时，扩展会放弃旧候选并重新识别；它不会主动切换地区。

## 库存变化与提交记录

- 平台明确提示库存不足，或“GPU库存发生变更，请刷新后重新选择”时，会按设置间隔刷新重试。库存可能在读取和提交之间被其他人使用，重试无法保证一定抢到。
- 提交后结果不明确、网络中断或出现其他需处理的弹窗时，会停止并保留记录，避免重复创建。
- **“存在未核实提交”时，先检查 AutoDL 实例列表。**确认没有创建新实例后，才点击“检查后重置提交状态”。旧版本遗留的提交记录也遵守这一流程。
- 若平台报告创建成功，扩展会停止，不继续创建第二个实例。
- 当前仅克隆系统盘，旧数据盘中的文件需要自行迁移。扩展不会修改、关机或删除源实例。

## 常见问题

### 进入页面后没有自定义面板

**先在克隆或新租用页面按一次 `F5` 或 `Ctrl+R`。这是当前版本的必需步骤。**

如果刷新后仍看不到，检查扩展是否已启用、是否已经登录 AutoDL，以及网址是否为 `https://www.autodl.com/create`，或包含有效 `id` 参数的 `https://www.autodl.com/cloneInstance`。

### 更新后仍显示旧版本

1. 用新版本文件覆盖 Chrome 实际加载的扩展文件夹。
2. 在 `chrome://extensions` 中点击本扩展的“重新加载”。
3. 回到 AutoDL 目标页面，**再手动刷新一次**，确认面板标题为 **v1.4.0**。

仅下载新压缩包或仅刷新网页，不会替换已经加载的旧扩展。更新时保留原扩展，不必卸载；卸载可能清除待核实提交记录。

### 库存有卡却没有抢

检查该型号是否满足所设显存门槛，以及该型号 **Top 3** 主机是否同时满足价格、CUDA、扩容和可选择状态。第 4 台及之后的主机不在当前检查范围内。

## 开发与验证

需要 Node.js 20 或更新版本。

```bash
npm install
npx playwright install chromium
npm test
```

只运行不依赖浏览器的核心测试：

```bash
npm run test:core
```

界面测试使用完全模拟的页面和独立浏览器环境，不连接真实 AutoDL、不读取个人浏览器资料，也不会提交付费订单。Windows 默认使用已安装的 Chrome；也可通过 `CHROME_PATH` 指定浏览器可执行文件，通过 `PLAYWRIGHT_PATH` 指定 Playwright 模块位置。

本地模拟测试覆盖克隆、新租用、镜像恢复、库存变更和防重复提交。已检查真实新租用页面的表格和镜像控件结构；尚未完成真实付费订单的端到端验证。自动操作依赖 AutoDL 网页结构，页面改版后可能需要更新。

更完整的行为、数据处理说明和型号显存参考来源见 [使用说明](使用说明.md)。
